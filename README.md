# **Here is the headline**
Earlier this year, I was working on a promotional poster for an exhibition project. I wanted to create a watercolour wash effect as the background. I clicked through every filter and channel tool in the software, but eventually found out that it simply didn't support that effect. Unless I wrote some CSS — which wasn't in my skillset.

That moment made me realise something: tools let you do what they can do, but only when you understand the language behind them can you make them do what *you* want.

So here I am. Not because I think design should become coding. But because I believe that for a designer, programming isn't an extra skill — it's an understanding of material. Like a craftsperson who understands fabric, or a cook who understands heat, a digital designer needs to understand the basic logic that builds the interfaces we work with: code.

# Tools and Materials

I compare programming to scissors and ovens because they are all tools. But what determines the quality of the work is never the tool itself — it's the user's understanding of the material.

Someone who has never held scissors can cut out a shape from paper. But to cut a well-fitting piece of clothing, they need to understand the fabric's grain, seam allowance, and how the structure fits together. Similarly, a designer who doesn't code can use design software to make beautiful static visuals. But if they want an interface or a poster to "respond to how people interact with it," they can only stay at the static level — or choose from preset templates, rather than actually *designing* the interaction itself.

My own experience proves this. For a class project last year, I made a simple interactive page. I wanted the background colour to shift gradually based on mouse movement. The tool I used didn't have that feature. I tried every workaround I could find, but none of them gave me the effect I wanted. In the end, I gave up on that idea and settled for something the tool already supported. That moment felt less like me controlling the tool, and more like the tool controlling what I could make.

That frustration wasn't about the tool being "bad." It was about me not knowing how to go beyond its preset limits. I had an idea in my head, but I lacked the language to translate it into reality. That's what I'm here to fix.
